```bash
cd wireframes

# → http://localhost:8000/            (index.html 플로우 허브)
```

## 2. 상태 스위처 사용법

각 화면은 `shared/wf.js`를 로드하고 인벤토리의 "상태 변형" 전부를 상태로 등록한다.
전환 경로는 2개 — ① URL 파라미터, ② 우상단 빗금 개발 툴바("제품 아님" 표기).

| 파라미터 | 값 | 동작 |
|---|---|---|
| `?state=` | 화면별 등록 목록 (예: `offline`, `error422`, `confirm`, `screen`, `redisplay`) | 상태 변형 전환. **미등록 값은 기본 상태로 폴백**(깨지지 않음) |
| `?lang=` | `hi` \| `en` | 환자측 언어 토글 — `html[lang]` + `html[data-lang]` CSS 토글(텍스트 노드 이중화). 약사측 UI는 영어 고정 |
| `?fx=` | `a` \| `b` \| `c` | 공용 픽스처 전환(`shared/fixtures.js`). fx 변경은 전체 리로드(재렌더 보장) |
| `?color=` | `1`(기본) \| `0` | `0` = 항목 배지 hue 오프 — "색은 보조 부호, 숫자가 정본" 검증 모드 |

파라미터는 조합 가능: `patient/s1-landing.html?fx=c&lang=en&color=0`.

**픽스처 3종** (`shared/fixtures.js` — 화면 하드코딩 금지, 관통 정합성의 원천):

- **FX-A 일상 3항목** — 자동완성 히트 시나리오. 3초 이해 테스트·탭 수 계측 기준 세트.
- **FX-B 전 패턴 10항목** — 코어 8패턴 + CUSTOM 포함 상한. 시간표 특수 행·최악 길이·무게 예산 검증.
- **FX-C 엣지** — 시드 밖 약명, ml 시럽, 0.5정(½), PRN, 별칭 유/무, version 2 "수정됨", D-3 "곧 만료".

예외: S1은 제품 동형 제약(전부 인라인·단일 문서)상 FX-A를 정적 마크업으로 렌더해 두고,
인라인 스크립트가 fixtures 데이터의 인라인 사본으로 fx/상태 전환을 담당한다.

## 3. 디자인 토큰 — astryx 증류 구조

```
shared/vendor/astryx-theme-neutral.css   ← 정본 (Meta astryx, neutral 테마)
        │  @scope + light-dark() 기반이라 직접 링크하지 않음
        ▼  라이트 모드 값만 증류 (변수명은 astryx 원명 유지)
shared/wf.css  :root { --color-text-primary; --color-background-card; --radius-element; … }
        │  + 공통 컴포넌트(배지·슬롯 스트립·칩·스테퍼·카드·하단 바·개발 툴바)
        ▼
각 화면 HTML (약사측: <link> · 환자측 S1: 인라인 복사 — 제품 동형 제약)
```

- **변수명 원명 유지**가 규약이다 — Figma/Flutter 이관 시 astryx 토큰 이름으로 1:1 추적 가능.
  vendor 파일을 수정하지 말 것. 증류값 변경이 필요하면 `wf.css`에서 고치고 `shared/TOKENS.md`에 기록.
- 항목 배지 10색 = astryx 10 hue의 `--color-icon-{hue}` (흰 숫자 대비 확보값).
  position 1..10 ↔ `.hue-1`..`.hue-10` 고정 매핑은 `wf.css` §9 참조.
- 라이트 고정(다크모드 없음), 웹폰트 로드 없음(Figtree 폴백 체인 그대로 → 시스템 폰트).
- 상세 표는 `shared/TOKENS.md`.
