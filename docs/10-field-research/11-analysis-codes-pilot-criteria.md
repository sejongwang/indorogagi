# 분석 코드 체계와 파일럿 판단 기준

> **이 문서에는 힌디 초안이 없다.** 참가자에게 읽는 문장이 없는 연구팀 내부 분석·판정 도구이므로, 힌디 초안 필수 규칙(환자·보호자·스크리너·동의문·환자 과업 지시문)의 적용 대상이 아니다. 태그·판정에 인용되는 원어 발화는 [10 문서 DB3](10-closing-notes-debrief.md)의 원어+번역 병기 원칙을 그대로 따른다.

- 결과물 섹션 14~15: **§2 분석 코드 체계(코드 트리 · 증거 강도 · 태깅 규칙 · 코드북 갱신)** / **§3 파일럿 진행(Go)·보류(Hold)·중단(Stop) 판단 기준**.
- 조사 지역: **[도시·주·병원 또는 약국 유형 입력]** — 권장 기본값 예시: 우타르프라데시 러크나우 등 힌디 벨트 Tier-2 도시([01 문서 §2.1](01-goals-participants-screener-consent.md)과 동일).
- 조사 인원: **[예상 인원 입력]** — 권장 기본값 예시: 총 28~38명([01 문서 §2.2](01-goals-participants-screener-consent.md)). 이 문서의 임계값 예시 인원은 이 기본값(환자 12~15명, 약사·조제보조 6~8명)을 기준으로 계산했다. 인원이 바뀌면 §3.2의 분모 정의에 따라 임계 인원을 다시 계산한다.
- 위치: 이 문서는 현장 도구(01~10)가 만든 원자료가 **분석 가능한 데이터(태그)** 가 되고, 태그가 **제품 의사결정(Go/Hold/Stop)** 이 되는 마지막 두 단계를 담당한다. 흐름: 질문지·과업·관찰 → 노트(NT)·디브리프(DB) → **태깅(§2)** → 지표 집계(PM) → **판정(§3)** → [01 문서 §1.1](01-goals-participants-screener-consent.md)의 "조사가 끝나면 결정할 것" 목록과 [01-dataflow.md](../01-dataflow.md) 결정 레지스터 반영.
- 참조: [01 문서](01-goals-participants-screener-consent.md)(목표 G1~G6·판정 신호·게이트 1~5), [02](02-questionnaire-patient.md)·[03](03-questionnaire-caregiver.md)·[04](04-questionnaire-pharmacist.md)·[05](05-questionnaire-doctor.md)·[06](06-questionnaire-nurse.md)·[07](07-questionnaire-hospital-ops.md) 질문지, [08 관찰 체크리스트](08-observation-checklist.md), [10 종료·노트·디브리프](10-closing-notes-debrief.md), [09 과업 문서](09-prototype-usability-tasks.md)(T-P1~T-P9·T-PH1~T-PH7), [01-dataflow.md](../01-dataflow.md)(§6.3 입력시간·KPI 정의, §1.3 결정 레지스터).
- 표기 주의: 병원 운영 질문 ID(H1~H20 문항, [07 문서](07-questionnaire-hospital-ops.md))와 핵심 가설(H1~H6)의 접두어가 겹친다. 이 문서에서 가설은 항상 **"가설 H#"** 로, 병원 질문은 **"H# 문항"** 으로 쓴다. 같은 이유로 "08 문서"·"09 문서"라는 라벨은 이 폴더(10-field-research)의 [08 관찰 체크리스트](08-observation-checklist.md)·[09 과업 문서](09-prototype-usability-tasks.md)만 가리키고, 상위 폴더의 카탈로그 문서(`../08-india-drug-data-foundation.md`, `../09-drug-catalog-operations.md`)는 번호 라벨 없이 항상 파일명으로 병기한다.

## 1. 이 문서의 사용 시점

### 1.1 도구별 사용 시점과 소요 시간

| 도구 | 사용 시점 | 소요 시간 |
|---|---|---|
| 현장 약식 표시(코드 약칭을 노트 여백에 메모) | 세션 중 | 추가 0분 (선택) |
| 본 태깅 (§2.5 TG 규칙) | 디브리프 직후 ~ 당일 일일 마감 | 참가자 1인당 5~10분 |
| 코드북 점검·갱신 (§2.7 CB 절차) | 첫 3건 완료 후 1회, 이후 5건마다 + 일일 마감 | 회당 20~30분 |
| 중간 가판정 (§3.8) | 목표 표본의 약 절반 시점 | 약 60분 |
| 최종 판정 회의 (§3.8) | 현장 조사 종료 후 3영업일 내 | 2~3시간 |

### 1.2 단축 운영 규칙

현장 일정이 밀려 본 태깅 시간이 안 나오는 날은 **하위 코드를 생략하고 대분류 + 증거 강도 + 방향만** 태깅한다(예: `COMP/E2/+`). 하위 코드 세분화는 일일 마감 또는 다음 날 아침에 소급한다. 대분류·강도·방향의 3요소는 어떤 경우에도 생략하지 않는다 — 이 3요소가 §3 판정 지표의 최소 입력이다.

### 1.3 원자료와 태그의 관계

- 태그는 원자료(노트 시트 NT, 디브리프 시트 DB, 탈리 시트 O, 과업 시트 T)를 **대체하지 않는다.** 태그 시트의 모든 행은 원자료의 참가자 코드·항목 ID로 되짚을 수 있어야 한다.
- 판정(§3)은 태그 집계와 원자료를 함께 본다. 태그 집계만으로 판정하지 않는다 — 집계가 임계값 근처면 반드시 원문 인용으로 돌아간다(§3.7 SS4·SS6).

## 2. 섹션 14 — 분석 코드 체계

### 2.1 태깅 대상과 단위

태깅 단위는 **스니펫**이다. 스니펫은 다음 넷 중 하나다.

1. 인터뷰 발화 한 토막 — 항목 ID 단위가 아니다. 한 답변(예: P1 여정 서술)에서 여러 스니펫이 나올 수 있다.
2. 과업 중 행동·발화 한 토막 — NT6 "멈춘 지점", 과업 시트의 행동 기록, 실측치.
3. 관찰 기록 한 건 — 탈리 소계, 환경 스냅숏의 사실, NT7 특이사항.
4. 말과 행동의 모순 기록 — 진술과 관찰·과업이 어긋난 사건([08 문서 관찰 원칙 3](08-observation-checklist.md)). 모순 자체가 하나의 스니펫이다.

**태그 표기법** (태그 시트 1행 = 스니펫 1개):

```
참가자코드 / 출처 ID / 코드 / 증거 강도 / 방향 / 근거 한 줄(행동·발화 원문)
예: P-07 / P2 / COMP-1 / E2 / + / "봉투의 1-0-1이 하루 한 알인 줄 알았다"
예: PH-03 / T-PH1 / TIME-1 / E1 / − / 항목당 active 실측 31초·28초·36초
```

- **방향 +** 는 "가설이 가정하는 문제·필요·제약이 실재한다"는 방향, **방향 −** 는 그 반대(문제 없음·제약 없음·수용) 방향이다. NT5의 지지/반박과 같은 축이다. 방향을 정할 수 없는 순수 맥락 정보(예: FLOW의 업무 단계 사실)는 `0`으로 적는다.
- 판단어("이해 못 함", "무관심")는 근거 칸에 쓸 수 없다. 근거는 행동·발화 원문 한 줄이다([08 문서 관찰 원칙 2](08-observation-checklist.md), [10 문서 §3.1-3](10-closing-notes-debrief.md)과 동일 원칙).

### 2.2 코드 트리 개요 — 대분류 11종

| 대분류 | 이름 | 정의 (무엇을 태깅하나) | 연결 가설 |
|---|---|---|---|
| **COMP** | 이해 실패 | 정보가 눈앞에 있는데도 뜻이 전달되지 않은 사건 — 표기·화면·개념의 해독과 재구성 실패 | H1 H2 |

경계 판정의 공통 규칙: **한 스니펫이 두 대분류에 걸치면 "행동을 최종적으로 결정한 요인"의 코드를 1차로 붙이고, 나머지를 2차로 붙인다**(최대 3개 — §2.5 TG3). 예: "사기 문자 경험 때문에(TRUST-2) 아들이 확인해 준 뒤에만 연다(TRUST-3)"는 TRUST-3이 1차다 — 여는 행동을 최종 결정한 것은 대리 확인이다.

### 2.4 증거 강도 3단계 (E1~E3)

모든 태그에 강도를 병기한다. 강도는 "무엇을 근거로 아는가"의 등급이며, §3 판정에서 서로 다른 무게를 갖는다.

| ID | 강도 | 정의 | 예시 | 판정에서의 취급 |
|---|---|---|---|---|
| **E1** | 직접 행동 관찰 | 연구자가 그 자리에서 본 행동·실측 — 과업 수행(T), 관찰(O), 세션 중 자연 발생 행동 | 과업에서 아침 약을 지목함 / 스캔 실패 3회 실측 / 카운터에서 봉투를 안 보고 주머니에 넣는 장면 | 판정 분자에 전액 산입. 동수일 때 우선(§3.7 SS3) |
| **E2** | 최근 사례 진술 | 구체적 최근 사건의 회상 — 언제·누가·어디서·무엇이 특정되는 이야기 | "지난주 화요일, 밤 약을 아침에 먹었다는 걸 며느리가 알았다" / "어제 그 손님께는 이렇게 말했다"(PH7) | 판정 분자에 산입 |
| **E3** | 일반화 의견 | 습관·경향·기대·추측·호감의 일반 진술 — 사건이 특정되지 않음 | "사람들은 보통 안 읽는다" / "이런 거면 다들 좋아할 거다" / "나는 항상 잘 챙긴다" | 판정 분자에 **넣지 않는다.** 방향 참고와 후속 질문 단서로만 사용 |

**강도 판정 규칙**

- 같은 참가자가 같은 내용을 E3(일반론)으로 말한 뒤 E2(구체 사례)로 뒷받침하면 E2 스니펫만 판정에 쓴다. E3→E2 강등·승격은 원문 기준이며 연구자가 "사례가 있겠지"라고 추정해 승격하지 않는다.
- 호감·칭찬·기대 발언("좋네요", "편하겠네요")은 강도와 무관하게 어떤 가설의 증거도 아니다([01 문서 §1.4](01-goals-participants-screener-consent.md), [10 문서 DB2](10-closing-notes-debrief.md)). 태그를 붙이지 않고 원자료에만 남긴다.
- 말과 행동이 어긋나면(E2 진술 ↔ E1 행동) E1을 판정에 쓰고, 모순 스니펫을 별도로 태깅한다(§2.1의 4번 유형). 모순은 CULT-3(체면) 또는 질문 설계 문제(DB6)의 단서다.

### 2.5 태깅 규칙 (TG1~TG10)

#### [TG1] (필수) 태깅 시점과 담당
- 본 태깅은 해당 세션의 **디브리프 직후~당일 일일 마감 안에** 그 세션의 진행자(또는 기록 담당)가 한다. 다음 날로 넘기면 기억이 아니라 노트만으로 태깅하게 되어 근거 한 줄의 질이 떨어진다. 통역 세션의 발화 스니펫은 DB3에서 확정된 원어+번역 인용을 쓴다.

#### [TG2] (필수) 스니펫 단위 준수
- 태그는 참가자 단위·항목 단위가 아니라 스니펫 단위다(§2.1). 한 참가자의 P1 답변에서 COMP-1과 MEM-2가 각각 나오면 두 행이다. 반대로 같은 사건을 여러 항목에서 반복 진술하면 한 행으로 합치고 출처 ID를 병기한다(중복 집계 방지).

#### [TG3] (필수) 다중 코드 상한
- 한 스니펫에 코드 최대 3개. 1차 코드는 "행동을 최종 결정한 요인"(§2.2)이며 집계의 기본값이다. 2·3차는 교차 분석용. 3개로 부족하면 스니펫을 쪼갠다 — 실제로는 사건이 2개 이상 섞여 있는 경우다.

#### [TG4] (필수) 강도·방향 필수 병기
- 코드만 있는 태그는 무효다. `코드/강도/방향` 3요소를 항상 채운다. 방향을 정할 수 없으면 `0`(맥락 정보)으로 적되, 방향 0 태그는 판정 분자에 들어가지 않는다.

#### [TG5] (필수) 근거 원문주의
- 근거 칸은 행동·발화 원문 한 줄이다. 판단어·요약 해석("이해 못 함", "신뢰 낮음")이 적혀 있으면 그 태그는 판정에서 제외한다. 원어 인용은 번역을 병기하되 원어를 지우지 않는다.

#### [TG6] (필수) 하위 코드 유보
- 하위 코드가 바로 안 정해지면 대분류에 `-0`을 붙여 유보한다(예: `TRUST-0`). 유보 태그는 일일 마감에서 해소하고, 해소되지 않는 유보가 반복되면 하위 코드 정의의 문제로 보고 CB 절차에 올린다.

#### [TG7] (필수) 반증 우선 점검
- 하루 태깅을 마치면 방향 −(반증) 태그가 0인 대분류를 확인한다. 반증이 하나도 없는 코드는 확증 편향의 신호일 수 있다 — 다음 세션에서 반증이 나올 수 있는 항목(예: 어려움 없이 복용을 재구성한 사례)을 의식적으로 듣고, 나오면 반드시 태깅한다. 반증 부재 자체를 일일 마감 기록에 남긴다.

#### [TG8] (필수) 이중 태깅 교정
- **첫 3건과 이후 매 5건째 세션은 두 사람이 독립적으로 태깅**하고 1차 코드 일치율을 확인한다. 일치율 70% 미만이면 어긋난 스니펫을 함께 재분류하고, 어긋남의 원인이 된 코드 정의를 CB 절차로 수정한다. 일치율 계산은 1차 코드 기준, 강도 불일치는 별도로 센다. 1인 조사라면 이 규칙 대신 하루 뒤 자기 재태깅(같은 세션을 노트만 보고 다시 태깅)으로 대체한다.

#### [TG9] (필수) 태그 시트 위생
- 태그 시트에도 개인정보 금지 규칙이 그대로 적용된다. 이름·연락처·진단명·실제 약 이름이 근거 인용에 섞이면 `[제외]`로 치환한다([01 문서 부록 A](01-goals-participants-screener-consent.md)). 참가자 코드와 서브그룹 코드(저문해·60+·피처폰·공용폰 등)는 반드시 병기한다 — §3의 서브그룹 분해가 이것에 의존한다.

#### [TG10] (선택) 현장 약식 표시
- 세션 중 노트 여백에 대분류 약칭만 흘려 적어 두면(예: "TR2?") 본 태깅이 빨라진다. 단, 약식 표시는 태그가 아니다 — 본 태깅에서 반드시 재검토하고, 세션 중 표시 행위가 참가자에게 채점처럼 보이지 않게 한다(원칙 7).

### 2.6 태그 집계 방식

- 집계 단위는 두 겹이다: **스니펫 수**(신호의 부피)와 **참가자 수**(신호의 확산). 판정(§3)의 임계값은 원칙적으로 참가자 수 기준이다 — 한 사람이 같은 문제를 다섯 번 말해도 판정 분자에서는 1명이다. 스니펫 수는 심각도·수렴 지점 분석에 쓴다.
- 집계표는 `대분류 × 방향 × 강도`의 참가자 수 매트릭스를 기본으로 하고, 판정 직전에 하위 코드 × 서브그룹 분해를 추가한다.
- 집계는 일일 마감에서 누적 갱신한다([10 문서 §4.5](10-closing-notes-debrief.md)의 가설별 증거 방향 집계와 같은 자리에서 한다).

### 2.7 코드북 갱신 절차 (CB1~CB6)

이 문서의 코드 트리는 **코드북 v1**이다. 갱신은 아래 절차로만 하고, 즉흥 수정을 금지한다.

#### [CB1] (필수) 갱신 시점
- 정기 점검: **첫 3건 완료 후 1회(파일럿 코딩), 이후 5건마다** + 일일 마감에서 경미한 예시 보강. 첫 점검(3건 후)이 가장 크게 바뀌는 것이 정상이다 — 현장 언어로 포함·제외 예시를 갈아 끼운다.
- 수시 점검 트리거: OTH가 전체 태그의 10% 초과 / TG6 유보 태그가 해소되지 않고 반복 / TG8 일치율 70% 미만.

#### [CB2] (필수) 신규 코드 추가 조건
- 같은 주제의 OTH 스니펫이 **서로 다른 참가자 3명 이상**에서 나오면 신규 하위 코드로 승격한다. 승격 시 정의·포함 예시·제외 예시·연결 가설을 이 문서 형식으로 작성해야 등록된다. 대분류 신설은 최종 판정 전에는 하지 않는다 — 판정표(§3)가 대분류에 걸려 있기 때문이다. 대분류가 필요해 보이면 기존 대분류의 하위로 우선 수용하고 판정 회의에서 재론한다.

#### [CB3] (필수) 분리·병합·동결 조건
- **분리**: 한 하위 코드가 그 대분류 태그의 50% 이상을 차지하고 내부에 이질적 묶음이 보이면 둘로 나눈다.
- **동결**: 5건 이상 진행 후에도 태그 0회인 하위 코드는 동결 표시한다. 삭제하지 않는다 — 동결 코드의 "0회"는 그 자체가 발견(예: 우려했던 PRIV-3이 실제로 없음)이므로 판정 회의에 보고한다.
- **병합**: 이중 태깅(TG8)에서 반복적으로 서로 혼동되는 두 코드는 정의를 다시 쓰거나 병합한다.

#### [CB4] (필수) 소급 재태깅
- 코드 정의가 바뀌면 **이전 세션의 해당 코드 태그를 전수 재검토**한다. 재검토 없이 신구 정의가 섞이면 집계가 무효가 된다. 소급 범위가 부담스러운 규모(10건+)가 되지 않도록 CB1의 초반 점검 주기를 지킨다.

#### [CB5] (필수) 변경 로그
- 모든 변경은 `코드북 버전 / 날짜 / 변경 내용 / 사유(계기가 된 스니펫 ID) / 소급 재태깅 완료 여부`로 로그에 남긴다. 판정 회의에는 최종 코드북 버전과 변경 로그 전체를 제출한다 — 임계값 판정이 "어느 정의 기준의 집계인가"에 답할 수 있어야 한다.

#### [CB6] (선택) 질문지 개선과의 연동
- 특정 코드가 특정 항목에서만 나오거나(질문이 답을 좁히고 있는 신호), 기대한 항목에서 전혀 안 나오면(질문이 닿지 않는 신호) DB6의 질문지 수정 후보로 넘긴다. 코드북과 질문지의 변경 로그는 분리해 관리한다.

## 3. 섹션 15 — 파일럿 진행·보류·중단 판단 기준

### 3.1 판정의 구조

- 판정 대상은 **가설 H1~H6 각각 + 운영·승인(OPS)** 의 7개이며, 각각 Go / Hold / Stop 중 하나를 받는다. 그 조합에 §3.4의 종합 규칙(JR)을 적용해 **파일럿 전체의 Go / Hold / Stop** 을 정한다.
- 판정의 뜻: **Go** = 이 가설에 관한 한 파일럿 설계를 확정하고 진행해도 된다. **Hold** = 진행 전에 §3.5의 추가 확인·수정·재검증이 필요하다. **Stop** = 현재 설계로는 기각 — §3.6의 피벗 후보로 방향을 바꾸거나 그 축을 포기한다.
- Stop은 "조사 실패"가 아니다. 파일럿 비용을 쓰기 전에 기각 근거를 확보한 것이 이 조사의 성공 조건 중 하나다.
- 판정 근거의 우선순위는 [01 문서 §1.2](01-goals-participants-screener-consent.md)의 지지/기각 신호 정의를 따르고, 이 문서는 그것을 계량 임계값으로 구체화한다. 임계값은 **사전 합의된 채택 규칙이지 통계 검정이 아니다**(§3.7 SS2).

**데이터 원천 지도**

| 원천 | 산출물 | 쓰이는 곳 |
|---|---|---|
| 과업 격자 NT6 + 과업 시트(T-P1~T-P9·T-PH1~T-PH7, [09 문서](09-prototype-usability-tasks.md)) | 과업별 성공/부분/실패, 실측치 | PM1 PM2 PM3 PM4 |
| 태그 집계(§2.6) | 대분류·하위 코드 × 방향 × 강도 × 참가자 수 | PM5 PM6 PM7 PM8 PM10 |
| 가설별 증거 원장(NT5·DB2 누적) | 참가자별 지지/반박/불명 | 전 판정의 교차 확인 |
| 관찰 탈리([08 문서 §7](08-observation-checklist.md)) | 되묻기·QR 장면·설명 시간의 현장 빈도 | PM3 PM6 PM7의 삼각검증 |

### 3.2 판정 지표 정의 (PM1~PM10)

분모 공통 규칙: 모든 비율의 분모는 **판정 가능 응답자**(해당 과업을 실시했거나 해당 질문에 실질 응답한 참가자)다. 건너뛰기·중단·미실시는 분모에서 빼되 건수를 판정 메모에 보고한다. 모든 비율은 분수 병기 의무(§3.7 SS1).

#### [PM1] 환자 핵심 과업 성공률
- **정의**: 환자 과업 핵심 4종 — **T-P2(아침 약 찾기) · T-P3(1회 복용량) · T-P4(식전·식후) · T-P5(복용 기간)** — 의 **무도움 성공률**. 무도움 성공 = 힌트 0회로 자력 지목·답변. 부분 성공 = 힌트 1회 후 완료(NT6 '부분'). 실패 = 힌트 2회 이상 또는 오답 유지.
- **산출**: 과업별 성공률 4개 + 4종 종합(참가자별로 4종 중 성공 개수의 분포). 과업별 세부 성공 판정 기준은 [09 문서](09-prototype-usability-tasks.md)의 확정 정의를 따른다. QR 스캔 과업은 **T-P1**이며 PM1이 아니라 PM3에서 집계한다 — 태깅·집계에서 두 지표의 과업 ID를 섞지 않는다.
- **원천**: NT6, 과업 시트. (가설 H2)

#### [PM2] 저문해 서브그룹 핵심 과업 성공률
- **정의**: PM1과 동일하되 분모를 저문해 서브그룹(S7 "타인 도움" 분류)으로 한정. 부분 성공을 별도 병기한다 — 저문해 참가자는 "힌트 1회 후 성공"과 "실패"의 차이가 설계 수정 가능성을 가른다.
- **원천**: NT6 × NT2 서브그룹 체크. 쿼터 미달(저문해 4명 미만 — [01 문서 §2.2](01-goals-participants-screener-consent.md)) 시 산출하지 않고 가설 H2를 자동 Hold(§3.7 SS5). (가설 H2)

#### [PM3] QR 스캔 자력 성공률
- **정의**: QR 스캔 과업(**T-P1**, [09 문서](09-prototype-usability-tasks.md))에서 **본인 또는 동행 가족의 폰으로, 진행자 개입 없이, 첫 화면 표시까지** 도달한 비율. 분모는 스마트폰 지참(본인+동행) 참가자. 재시도는 허용하며 회수를 기록한다. 진행자·약사가 폰을 받아 대신 스캔한 경우는 분자에서 제외하고 TECH-4로 태깅한다(파일럿 KPI의 대리 스캔 정의와 다름 — 여기서는 "자력"을 검증한다).
- **보조 산출**: 실패 원인 분해(TECH-1 하위 사유), 백업 코드 경로 복구율. (가설 H3)

#### [PM4] 약사 항목당 입력 시간
- **정의**: T-PH1 시연 입력의 **항목당 active 시간**([01-dataflow §6.3](../01-dataflow.md)의 단위 정의를 따른다 — 인터럽트 구간 제외, 처방 전체가 아니라 항목당). 산출: 참가 약사별 대표값과 전체 p50, 개인별 최악값. 스톱워치 실측이면 인터럽트 구간을 랩으로 제외한다.
- **비교 기준선**: 같은 참가자의 PH13 현행 입력 실측치. "현행 청구 입력보다 얼마나 더 얹는가"가 절대값 못지않게 중요하다. (가설 H5)

#### [PM5] 약사 수용·거부 신호
- **정의**: 시연 직후 자발 발언의 분류 — ① **수용**(피크·비피크 운영 방식을 스스로 제안: TIME-3/+가 아닌 구체 운영안), ② **조건부**("~라면 하겠다"의 조건 명시), ③ **거부**(명시적 불가 발언). 분모는 T-PH 과업 완료 약사. 유도 질문으로 만든 답은 세지 않는다 — 자발 발언 또는 개방형 후속(W3 계열)의 답만 센다.
- **원천**: TIME-3·RISK 태그 + 과업 시트. E3 일반론("다들 좋아할 거다")은 세지 않는다. (가설 H5)

#### [PM6] 신뢰 거부 신호율
- **정의**: 환자·보호자 중 다음 하나 이상이 확인된 비율 — ① 과업에서 스캔·링크 열기를 실제로 사양·회피(E1), ② 사기 경험 기반 회피의 구체 사례(TRUST-2/E2). 조건부 신뢰(TRUST-3 대리 판단)는 거부로 세지 않고 별도 비율로 병기한다.
- **보조 산출**: 신뢰 성립 단서(TRUST-1) 중 "약사·약국이 그 자리에서 줌"의 자발 언급률. (가설 H4)

#### [PM7] 혼란·실수 사례 보유율
- **정의**: 환자·보호자 중 최근 복용기(대체로 최근 30일)에 대해 **E2 이상의 구체적 혼란·오복용·재확인 사례**를 1건 이상 말한 비율. COMP·MEM 계열 +방향 E1/E2 태그 기준. "헷갈린 적 없다"는 명시 답변은 **분모에 포함하되 분자에 넣지 않고**, 방향 − 참고 신호로 판정 메모에 병기한다 — 사건이 특정되지 않은 일반 진술이므로 그 자체는 판정 증거가 아니다(§2.4 E3). 어려움 없이 재구성한 최근 구체 사례로 뒷받침되면 E2 −로 태깅한다.
- **삼각검증**: 관찰 탈리의 되묻기(O10·O19)·봉투 미확인(O11) 빈도, 약사 측 증언(PH3·PH8)과 대조. (가설 H1)

#### [PM8] 가족·보호자 관여율
- **정의**: 환자 중 복약의 기억·수령·판독·결정에 타인이 관여함이 E1/E2로 확인된 비율(MEM-3, LANG-3, TRUST-3, CULT-1의 +방향 태그 합집합, 참가자 단위). 보조: 약사 측 대리 수령 어림(PH11), 관찰 동행 비율(O13·O23), 디지털 공유의 실사례(PRIV-2/E2) 보유율.
- (가설 H6)

#### [PM9] 파일럿 승인 경로 확보도
- **정의**: 현장 유형별 체크리스트 충족 수.
  - 약국 1곳 기준 3항목: ① 도입 결정권자 식별(PH18로 확인) ② 결정권자 또는 참가 약사의 재연락 동의(W15) ③ 명시적 거부·차단 신호 없음.
  - 병원(파일럿에 병원 접점을 넣는 경우만): ① 승인 체인 지도 작성 가능(D19·H19 문항) ② 체인 위 실명 접점 1인 이상과 재연락 동의 ③ 예상 승인 기간이 파일럿 일정과 양립.
- **산출**: 3항목을 모두 충족한 약국 수(파일럿 후보 수). (게이트 5)

#### [PM10] 차단급 위험 수
- **정의**: RISK 태그 중 판정 회의에서 **차단급**으로 합의된 위험의 수. 차단급 = 완화책 없이는 파일럿을 시작할 수 없거나 시작 후 중단시킬 수 있는 요인(예: 책임 귀속 우려로 인한 약국주 거부가 복수 현장에서 일관, 승인 체인이 일정상 불가능, 규제 저촉 소지). 차단급 판정은 참석자 전원 합의로만 하고, 합의 불발 시 차단급으로 **간주한다**(보수 원칙).
- (게이트 5)

### 3.3 가설별 판정표 (GS-H1~GS-H6, GS-OPS)

각 표의 계량 기준과 정성 신호는 **병용 조건**이다 — 계량이 충족돼도 정성 신호가 반대면 §3.7 SS6(삼각검증)으로 내려 경계 판정한다. 예시 인원은 환자·보호자 판정 가능 분모 12명, 약사 6명 가정의 환산값이며 실제 분모로 재계산한다. 구간 표기 공통 규칙: 판정과 경계 폭(JR6)은 **인원 기준을 정본**으로 읽고, 괄호의 비율은 분모가 바뀔 때 임계 인원을 다시 계산하기 위한 기준값이다. 구간은 서로 겹치지 않게 반개구간("이상~미만")으로 읽으며, 정확히 임계값에 놓인 값이 두 행에 동시에 해당하는 표기를 두지 않는다. 각 표의 마지막 행은 기본행이다 — **위 어느 행에도 해당하지 않는 조합은 Hold로 분류하고 판정 메모에 사유를 남긴다.**

#### [GS-H1] 가설 H1 — 표기만으로는 이해가 어렵다 (게이트 1: 문제 실재성)

| 판정 | 계량 기준 | 병용 정성 신호 |
|---|---|---|
| **Go** | PM7 ≥ 8명 (8/12, 약 67% — 60% 이상 구간) | 관찰에서 되묻기·봉투 미확인이 실재(O10·O11 탈리 0이 아님)하고, 약사 증언(PH3·PH8)의 혼동 주제가 **서로 다른 2개 현장 이상**에서 교차 |
| **Hold** | PM7 4~7명 (4/12~7/12, 33~58%) | 사례가 특정 서브그룹(고령·다제복용 등)에 집중 — 문제는 실재하나 타깃 정의가 좁아져야 함 |
| **Stop** | PM7 ≤ 3명 (3/12, 25% 이하) | 관찰 블록에서도 되묻기·표기 참조 실패가 거의 없음(30분 블록당 0~1건 수준)이고 방향 − 태그가 우세 |
| **기본(Hold)** | 위 어느 행에도 해당하지 않는 조합 | Hold로 분류하고 판정 메모에 사유를 남긴다 |

- 판정 주의: 되묻기 부재는 이해의 증거가 아니다(CULT-2 권위 관계로 억눌릴 수 있다). Stop 판정 전에 CULT-2 태그량을 반드시 확인하고, 많으면 "질문을 못 하는 것"과 "궁금한 게 없는 것"을 과업 결과(PM1의 재구성 실패 여부)로 가른다.

#### [GS-H2] 가설 H2 — 숫자·색·아이콘·짧은 문장 결합 화면이 이해를 돕는다 (게이트 2)

| 판정 | 계량 기준 | 병용 정성 신호 |
|---|---|---|
| **Go** | PM1 4종(T-P2~T-P5) 각각 무도움 ≥ 9명 (9/12, 75% 이상) **그리고** PM2 저문해 무도움+부분 합산 ≥ 3/4명 **그리고** 치명 오독(용량·시간대를 반대로 확신) 0건 | 오독(COMP-3)이 있어도 특정 요소 1~2개로 수렴하고 수정 방향이 태그에서 보임 |
| **Hold** | PM1 어느 한 과업이 6~8명 (6/12~8/12, 50% 이상 75% 미만), 또는 PM2 미달, 또는 치명 오독 1~2건이 특정 요소로 수렴 | 실패가 특정 화면 요소·어휘(LANG-4)에 몰림 — 해당 요소 수정 후 재검증으로 회복 가능 |
| **Stop** | PM1 4종 종합에서 절반 이상의 참가자가 2종 이상 실패, 또는 저문해 전원이 화면 판독을 타인에게 위임(LANG-3/E1) | 실패가 요소별로 분산되어 수정 목표가 안 잡히고, 방향 − 신호(화면 무시·구두 재확인 고집)가 서브그룹 불문 일관 |
| **기본(Hold)** | 위 어느 행에도 해당하지 않는 조합 | Hold로 분류하고 판정 메모에 사유를 남긴다 |

- 판정 주의: 저문해 쿼터([01 문서 §2.2](01-goals-participants-screener-consent.md) 최소 4명) 미달 시 자동 Hold(SS5). 치명 오독은 §2.6 참가자 수 원칙의 **명시적 예외**로, 발생 건수 단위로 센다(한 참가자가 2건을 내도 2건 — 안전 관련 신호이므로). 부분 성공(힌트 1회)의 힌트 내용이 "화면을 가리킴"이었는지 "답을 말해 줌"이었는지를 원자료에서 구분한다 — 후자는 성공이 아니다.

#### [GS-H3] 가설 H3 — 무설치 QR 접근이 현장에서 작동한다 (게이트 3 전반부)

| 판정 | 계량 기준 | 병용 정성 신호 |
|---|---|---|
| **Go** | PM3 ≥ 7명 (예: 스마트폰 지참 10명 중 7명, 70% 이상) **그리고** 실패 건 전원이 백업 경로(재시도·백업 코드·가족 폰)로 복구 | UPI QR 습관이 현장에서 확인(O12 탈리·PH16)되고, 연결 실패(TECH-2)가 산발적 |
| **Hold** | PM3 4~6명 (4/10~6/10, 40% 이상 70% 미만), 또는 PM3 구간과 무관하게 백업 경로 복구 실패 1~2건 | 실패 원인이 교정 가능한 축(인쇄 크기·대비·조도·안내 위치)으로 수렴(TECH-1 사유 분해), 또는 공용폰·가족 폰 의존이 우세해 재열람 경로가 불투명(ACCESS-3) |
| **Stop** | PM3 ≤ 3명 (3/10, 40% 미만)이고 백업 경로 복구도 실패 건의 절반 미만, **또는** 스마트폰 접근(본인+동행 합산) 가능 참가자가 전체 표본의 50% 미만 | QR 개념 자체가 부재한 참가자가 다수(P10에서 "QR"을 모름)이고 UPI 습관도 관찰되지 않는 상권 |
| **기본(Hold)** | 위 어느 행에도 해당하지 않는 조합(예: PM3 40% 미만이나 백업 복구 양호) | Hold로 분류하고 판정 메모에 사유를 남긴다 |

- 판정 주의: 피처폰·무폰 참가자는 PM3 분모에서 빠지므로, **분모에서 빠진 비율 자체**를 Go 판정문에 병기한다(예: "PM3 80% — 단, 표본의 3할이 스마트폰 비접근"). 이 비율이 크면 Go여도 대체 경로(가족 폰·인쇄물) 설계를 파일럿 범위에 포함한다.

#### [GS-H4] 가설 H4 — 약사·병원이 준 QR 링크를 신뢰한다 (게이트 3 후반부)

| 판정 | 계량 기준 | 병용 정성 신호 |
|---|---|---|
| **Go** | PM6 ≤ 2명 (2/12, 약 17% 이하) **그리고** 과업 중 실제 거부(E1) ≤ 1명 | "약사가 그 자리에서 줬다"는 신뢰 단서(TRUST-1)의 자발 언급이 절반 이상 |
| **Hold** | PM6 3~4명 (3/12~4/12, 25~33%), 또는 대리 판단(TRUST-3) 우세 | 거부의 근거가 화면 요소(발급 주체 표기 부재 등)로 수렴 — 신뢰 표시 재설계로 회복 가능. 또는 여는 것은 하되 내용을 믿지 않는 행동(구두 재확인 고집, TRUST-4) |
| **Stop** | PM6 ≥ 5명 (5/12, 약 42% 이상)이고 사기 경험 기반 회피가 서브그룹 불문 일관 | 대면 발급·약국명 표기 등 어떤 단서로도 거부가 풀리지 않고, 종이 요구가 절대적 |
| **기본(Hold)** | 위 어느 행에도 해당하지 않는 조합(예: PM6 ≥ 5명이나 회피가 특정 서브그룹에 국한) | Hold로 분류하고 판정 메모에 사유를 남긴다 |

- 판정 주의: 거부는 존중된 권리 행사이지 실패가 아니다 — 거부 참가자에게 이유를 추궁한 기록은 판정에 쓰지 않는다. 조사자가 신뢰를 유도한 흔적(원칙 3 위반)이 있는 세션의 TRUST +태그는 분자에서 제외한다.

#### [GS-H5] 가설 H5 — 약사 추가 입력 시간이 현장에 들어간다 (게이트 4)

| 판정 | 계량 기준 | 병용 정성 신호 |
|---|---|---|
| **Go** | PM4 p50 ≤ 40초 **그리고** 개인별 최악값 ≤ 60초인 약사가 2/3 이상 (6명 중 4명+) **그리고** PM5 수용(자발 운영안) ≥ 2명·명시 거부 ≤ 1명 | 현행 미룸·생략 경계(TIME-2) 대비 입력량이 수용 범위라는 발언이 실측과 모순되지 않음. 피크 운영안(미루기·백업 코드 활용)이 약사 입에서 나옴 |
| **Hold** | PM4 p50 40초 초과 60초 이하, 또는 멈춤이 특정 필드로 수렴(T-PH1 멈춘 지점 기록), 또는 수용·거부 발언이 혼재 | 지연 원인이 폼 설계(검색·필드 수·패턴 버튼)로 수렴해 수정 여지가 있음(FLOW·TIME 태그 분해). 자동완성 히트 항목과 자유 입력 항목의 시간 차가 크면 카탈로그 보강으로 회복 가능([01-dataflow §6.3](../01-dataflow.md)) |
| **Stop** | PM4 p50 > 60초이고 지연이 구조적(폼 수정으로 안 잡히는 해독·전사 자체의 부담), **또는** 전원이 피크·비피크 모두 불가를 일관 진술하고 운영안 제안 0건 | 시연 중 이탈·중단이 반복되고, RISK-2(책임)·RISK-3(유인 부재)가 시간과 독립적으로 강함 |
| **기본(Hold)** | 위 어느 행에도 해당하지 않는 조합(예: p50 > 60초이나 지연이 구조적이지 않음) | Hold로 분류하고 판정 메모에 사유를 남긴다 |

- 판정 주의: PM4는 시연 실측이므로 학습 효과 이전의 값이다 — 같은 참가자의 2~3회차 입력이 있으면 추세(감소 여부)를 병기한다. PH13 현행 실측 대비 "덧얹는 양"이 절대값보다 설득력 있는 근거가 되는 경우가 많다.

#### [GS-H6] 가설 H6 — 가족·보호자가 함께 확인할 필요가 있다

| 판정 | 계량 기준 | 병용 정성 신호 |
|---|---|---|
| **Go** | PM8 ≥ 6명 (6/12, 50% 이상) **그리고** **서로 다른 참가자 3명 이상**의 디지털 공유 실사례(PRIV-2/E2 — §2.6 참가자 수 원칙 그대로) | 대리 수령·대독·원격 지시의 구체 장면이 여러 원천(P·C·PH11·O13)에서 교차 |
| **Hold** | PM8 4~5명 (4/12~5/12, 33~42%), **또는** PM8 ≥ 6명이나 공유가 구두·대면 위주로 디지털 채널 실사례 보유자가 3명 미만, 또는 PRIV-1 노출 우려가 공유 실태와 혼재 | 관여 구조는 확실한데 링크 공유가 그 구조에 맞는지 불명 — 공유 기능의 v0 범위(D12 `?lang=` 보존 공유)만 유지하고 확장은 보류 |
| **Stop** | PM8 ≤ 3명 (3/12, 25% 이하)이고 공유에 대한 거부·우려가 우세 | 복약 관리가 개인 단위로 일관되고, 가족 열람이 오히려 회피 대상(PRIV-1/E2 다수) |
| **기본(Hold)** | 위 어느 행에도 해당하지 않는 조합(예: PM8 ≤ 3명이나 거부·우려가 우세하지 않음) | Hold로 분류하고 판정 메모에 사유를 남긴다 |

- 판정 주의: **가설 H6의 Stop은 파일럿 전체를 막지 않는다** — 공유·보호자 기능의 우선순위 결정([01 문서 G6](01-goals-participants-screener-consent.md))에만 작용한다(§3.4 JR5). 여성·고령 참가자의 쿼터 미달 시 PM8은 과소 추정될 수 있다(약국 앞 인터셉트 편향, DB7) — 미달 상태의 Stop 판정은 금지한다.

#### [GS-OPS] 운영·승인 — 파일럿을 막는 위험 (게이트 5)

| 판정 | 계량 기준 | 병용 정성 신호 |
|---|---|---|
| **Go** | PM9 파일럿 후보 약국 ≥ 2곳 **그리고** PM10 = 0 | RISK 태그가 존재해도 전부 완화책과 짝지어짐(예: 책임 우려 → 화면에 발급 주체·정정 절차 명시로 수용 발언 확보) |
| **Hold** | PM9 = 1곳, 또는 PM10 = 1건(완화책 설계가 필요) | 승인 경로는 보이나 기간·결재자가 미확정(RISK-1), 또는 유인 설계(RISK-3)가 미해결 |
| **Stop** | PM9 = 0곳이고 섭외 거부의 이유가 유인 부재·책임 우려로 일관, 또는 PM10 ≥ 2건이 구조적(완화책이 제품 밖에 있음) | 도구 이탈 이력(RISK-5)이 "우리 같은 도구"의 실패 패턴을 반복적으로 가리킴 |
| **기본(Hold)** | 위 어느 행에도 해당하지 않는 조합(예: PM9 = 0곳이나 거부 사유가 비일관이고 PM10 = 0) | Hold로 분류하고 판정 메모에 사유를 남긴다 |

- 판정 주의: 조사와 계약 논의는 분리돼 있으므로([04 문서 진행 규칙 11](04-questionnaire-pharmacist.md)) PM9의 "긍정 신호"는 참여 약속이 아니라 재연락 동의와 결정권자 식별까지다. 병원 항목은 파일럿 v0 범위(약국 진입점)에 병원이 없으면 판정에서 제외하고 정보 수집 결과만 기록한다.

### 3.4 종합 판정 규칙 (JR1~JR7)

판정 순서: **JR6(가설별 판정 확정 — 경계 강등 포함) → JR2 → JR3 → JR4 → JR7 → JR1 → JR5.** 먼저 JR6로 가설별 Go/Hold/Stop을 확정한 뒤, 확정된 조합에 대해 중단(Stop) 조건부터 확인하고 Go를 마지막에 선언한다(§3.8 최종 판정 회의의 ②→③ 순서와 동일).

#### [JR1] (필수) 전체 Go의 조건
- **가설 H1·H2·H3·H5와 OPS가 모두 Go**이고, 가설 H4가 Go 또는 Hold일 때 전체 Go. 가설 H4가 Hold인 Go는 **조건부 Go**로 선언하고, 신뢰 표시 요소의 수정 항목(GS-H4 Hold의 수렴 지점)을 파일럿 시작 전 필수 반영 목록에 넣는다. 가설 H4가 Stop이면 이 경로가 아니라 JR7(단일 가설 Stop)로 처리한다. 가설 H6은 전체 판정에 관여하지 않는다(JR5).
- 전체 Go 선언문에는 [01 문서 §1.1](01-goals-participants-screener-consent.md)의 목표별 "결정할 것" 각각에 대한 결정 초안(화면 우선순위·전달 경로·운영 규칙 등)을 첨부해야 한다 — 결정 없는 Go는 무효다.

#### [JR2] (필수) 즉시 전체 Stop
- **가설 H1이 Stop이면 다른 판정과 무관하게 전체 Stop.** 해결할 문제가 실재하지 않으면 나머지 축의 성적은 의미가 없다. 피벗은 PV-H1.

#### [JR3] (필수) 복합 Stop
- **가설 H2와 H3이 동시에 Stop이면 전체 Stop** — 이해 수단과 전달 수단이 모두 무효인 상태는 부분 수정으로 회복되지 않는다. 피벗은 PV-H2·PV-H3의 교집합(비화면·비QR 대안)에서 찾는다.
- **가설 H5가 Stop이고 §3.6 PV-H5의 입력 주체·방식 피벗이 판정 회의에서 실행 불가로 결론나면 전체 Stop.** 실행 가능해 보이면 전체 Hold로 두고 피벗안을 재검증한다.
- **OPS가 Stop이면 전체 Hold가 상한**이다(제품이 좋아도 운영이 막힌 상태). 지역·현장 유형 변경으로 풀리는지 확인한 뒤, 안 풀리면 Stop.

#### [JR4] (필수) Hold의 전파
- JR2·JR3에 걸리지 않고 **가설 H1·H2·H3·H5·OPS 중 하나라도 Hold면 전체 Hold.** 가설 H4의 Hold는 이 규칙으로 전파하지 않고 **JR1의 조건부 Go 경로로 처리한다** — 단, 가설 H4의 Hold와 위 목록의 다른 Hold가 동시에 발생하면 전체 Hold다. Hold 항목마다 §3.5의 해당 HQ 목록을 소화하는 계획(방법·기간·판정 재기준)을 판정 메모에 명시해야 Hold 선언이 성립한다.
- **재판정은 1회로 제한한다.** 같은 가설이 두 번째 Hold를 받으면 무한 보류를 막기 위해 Stop 요건으로 재심사한다 — "한 번 더 고치면 될 것 같다"는 세 번째 기회의 근거가 되지 못한다.

#### [JR5] (필수) 가설 H6의 별도 트랙
- 가설 H6의 판정은 전체 Go/Hold/Stop에 관여하지 않고 **기능 범위 결정**으로만 흐른다: Go → 공유·보호자 요소를 파일럿 v0에 유지(D12 공유 URL 언어 보존, `patient_label` 활용). Hold → v0 최소 유지 + 파일럿 계측으로 재판정(공유 유입 신호, [01-dataflow §6.4](../01-dataflow.md)). Stop → 공유 기능을 v0에서 제거하고 개인 단위 설계로.

#### [JR6] (필수) 경계 판정 규칙
- 어떤 지표든 임계값의 **±1명 이내**면(인원 기준이 정본이며, 비율 환산 표기는 참고용이다) 그 지표는 "경계"로 표기하고 계량만으로 판정하지 않는다. 경계 지표는 §3.7의 SS3(강도 구성)·SS4(하나 빼기)·SS6(삼각검증)을 적용해 가른다.
- 한 가설 안에서 경계 지표가 2개 이상이거나, 전체에서 경계가 3개 이상이면 해당 판정은 자동으로 보수 쪽(Go→Hold, Stop→Hold)으로 내린다.
- 이 규칙은 판정 순서상 **가장 먼저**(가설별 판정을 확정하는 단계에서) 적용한다 — 경계 강등을 거치지 않은 가설별 Stop/Go에 JR2~JR4를 적용하지 않는다.

#### [JR7] (필수) 잔여 조합 규칙
- JR2·JR3에 해당하지 않는 **단일 가설의 Stop**(가설 H2·H3·H4 단독 Stop 포함)은 **전체 Hold**로 내리고, 해당 가설의 PV 후보(§3.6)의 실행 가능성을 판정 회의에서 심사한다 — 실행 불가로 결론나면 그 자리에서 전체 Stop으로 격상할 수 있다.
- JR1~JR4의 어느 규칙에도 해당하지 않는 조합은 **전체 Hold를 기본값**으로 하고, 어떤 조합이 왜 미정의였는지를 판정 메모에 남긴다.

### 3.5 Hold일 때 추가로 알아야 할 것 (HQ-H1~HQ-H6, HQ-OPS)

Hold는 "더 조사한다"가 아니라 "무엇을 알면 판정이 갈리는지"를 특정하는 것이다. 각 항목은 후속 활동의 최소 설계(무엇을·누구에게·어떻게)를 함께 적는다. §3.3의 판정 대상 7개(가설 H1~H6 + OPS) 각각에 대응하는 HQ 목록이 있어야 JR4의 Hold 성립 요건을 채울 수 있다.

#### [HQ-H1] 가설 H1 Hold — 문제의 위치 특정
- 혼란 사례가 집중된 세그먼트(고령·다제복용·초회 처방)와 표기 유형("1-0-1"형·약어형·수기 흘림)은 무엇인가 → 태그 재분해 + 해당 서브그룹 표본 보강(스노볼 W6 활용).
- 되묻기 부재가 이해인가 침묵인가 → 관찰 세션 추가(O10 되묻기 탈리를 피크·비피크 각 1블록 이상) + 과업 재구성 결과와 교차.
- 문제가 "이해"가 아니라 "기억"에 있는가(COMP 대비 MEM 태그 비중) → 화면 설계 우선순위를 정보 이해에서 재참조 편의로 옮길지의 근거.

#### [HQ-H2] 가설 H2 Hold — 실패 요소의 교정 검증
- 실패가 수렴한 요소(아이콘·색·시간대 어휘·숫자 표기)의 수정판을 만들어 **동일 과업 재검증** — 수정은 한 번에 2개 요소 이하로 제한해 효과를 분리한다(DB6의 수정 상한과 같은 원리).
- 힌디 어휘(특히 시간대·식전후)의 원어민 검수를 완료한 뒤의 성공률인가 — 검수 전 결과라면 어휘 요인과 시각 문법 요인을 분리해야 한다.
- 음성 안내를 추가하면 저문해 실패가 회복되는가 → 음성 유무 2조건 비교 과업(가능하면 동일 참가자 재방문, W15 재연락 동의자 활용).

#### [HQ-H3] 가설 H3 Hold — 실패 축의 분해와 대체 경로
- 실패 원인 분포(카메라 성능/조도/인쇄 품질/데이터/앱 선택)를 TECH-1 하위 사유로 재집계 → 교정 가능 축이면 인쇄 크기·대비·위치 변형안으로 현장 재시험.
- 공용폰·가족 폰 시나리오의 재열람 경로 — 링크가 남의 폰에 있을 때 환자가 다시 보는 실제 방법이 있는가(백업 코드 `/c` 경로·재방문 시 재표시, [01-dataflow §2.4](../01-dataflow.md)) → 해당 참가자 유형으로 재과업.
- 백업 코드 안내 방식(구두·인쇄·게시)별 자력 복구율 차이.

#### [HQ-H4] 가설 H4 Hold — 신뢰 단서의 조작 검증
- 거부·주저가 수렴한 화면 요소는 무엇인가(발급 주체 표기·약국명·URL 모양) → 신뢰 표시 변형안 2종 이하로 비교 과업.
- 대리 판단(TRUST-3)이 우세하면 — 검증 대상을 판단 위임자(가족)로 넓혀 보호자 대상 신뢰 과업을 추가한다(C 질문지 참가자군).
- 상태·만료 화면(COMP-4)이 의심을 키우는가 — 만료 문구 변형안의 이해·신뢰 반응.

#### [HQ-H5] 가설 H5 Hold — 지연·거부 원인의 폼 수준 특정
- 멈춘 필드의 수정판(필드 수 축소·패턴 버튼·자동완성 보강) 재실측 — 목표는 p50의 재판정이 아니라 **수정 전후 차이**의 확인.
- 자동완성 히트율이 낮은 지연이면 카탈로그 기반 문서([08-india-drug-data-foundation.md](../08-india-drug-data-foundation.md)의 데이터 축, [09-drug-catalog-operations.md](../09-drug-catalog-operations.md)의 운영 절차 — 이 폴더의 08·09 문서와 다른 파일이다, 상단 표기 주의 참조)를 따라 카탈로그를 보강한 뒤 재실측 — 폼 문제와 데이터 문제를 분리한다.
- 피크 운영안(입력 미루기·백업 코드 선지급)의 현장 시뮬레이션 — 미룬 입력이 실제로 그날 안에 이뤄지는가(TIME-2 경계와 대조).
- 수용·거부가 갈린 약사의 프로필 차이(1인 운영/다인, 고회전/저회전, 프린터 유무) — 파일럿 약국 선정 기준으로 환산.

#### [HQ-H6] 가설 H6 Hold — 공유 구조의 채널 확인
- 관여는 있는데 디지털 공유가 빈약한 이유 — 채널 부재인가(WhatsApp 미사용층), 규범인가(PRIV-1), 필요 부재인가(대면 동거) → 원거리 보호자 서브그룹 보강 조사.
- 공용폰 가구에서 링크가 실제로 누구 폰에 남고 누가 다시 여는가 — 가구 단위 시나리오 재과업.
- `patient_label`(별칭)이 다인 가구의 혼동을 실제로 줄이는가 — 여러 명 분 화면을 구분하는 과업.

#### [HQ-OPS] 운영·승인 Hold — 승인 경로와 차단급 위험의 해소 조건
- PM9가 1곳에 그친 원인의 특정 — 미확보 약국의 미충족 항목(결정권자 미식별/재연락 미동의/거부 신호)을 체크리스트 항목별로 재집계하고, 미확정 결재자·승인 기간은 재연락 동의자(W15)를 통해 특정한다.
- PM10 = 1건인 차단급 위험의 완화책 설계 — 완화책 초안을 만들고 해당 약국주·결정권자에게 재확인한다(예: 책임 귀속 우려 → 화면의 발급 주체·정정 절차 표시안 제시 후 수용 발언 여부 확인). 완화책이 제품 밖(제도·규제)에 있으면 Stop 요건으로 재심사한다.
- 유인 설계 대안(RISK-3)의 수용 여부 — 후보 약국이 받아들이는 유인 형태(차별화·고객 서비스·업무 절감)를 재연락 인터뷰로 확인하고, 파일럿 합의 문서 초안의 입력으로 넘긴다.
- 후보 확보 실패가 지역·현장 유형의 문제인지 — 다른 상권·약국 유형(1인 운영/다인, 병원 인근/주거지)의 섭외 1~2곳을 추가 시도해 분리한다.

### 3.6 Stop일 때의 피벗 후보 (PV-H1~PV-H6)

피벗은 판정 회의에서 "다음 조사·설계의 출발점"으로 1~2개를 고른다. 전부 추진하지 않는다.

#### [PV-H1] 가설 H1 Stop — 문제 재정의
- **세그먼트 피벗**: 일반 외래가 아니라 문제가 실증된 좁은 집단(다제복용 만성질환·고령·퇴원 직후·소아 보호자)으로 타깃 재정의 후 재조사.
- **지역 피벗**: 표기·설명 관행이 다른 지역(저문해율·언어 구성이 다른 주)에서 문제 실재성 재검 — 단, "문제가 있는 곳을 찾을 때까지 옮기기"가 되지 않게 사전 기준을 세운다.
- **문제 전환**: 환자 이해가 아니라 약사 측 부담(수기 처방 해독·기록·정정)을 해결하는 약국 내부 도구로 방향 전환 — PH3·PH6·FLOW 태그가 강하면 이 전환의 근거가 이미 있다.

#### [PV-H2] 가설 H2 Stop — 이해 수단 교체
- **음성 우선**: 화면은 최소로 두고 음성 안내(자동 재생·전화 회신형)를 1차 수단으로 — P13(음성 메시지 습관) 태그가 강할수록 유력.
- **실물 우선**: 디지털 화면 대신 봉투 스탬프·스티커·그림 카드 등 인쇄 시각물 체계([05 문서](../05-india-medication-poster-research.md)의 시각 문법을 실물로) — 약사 표기 관행(PH4)에 얹는 설계.
- **보조 도구 전환**: 환자 자가 열람이 아니라 **약사가 설명하며 보여주는** 카운터 화면(설명 표준화 도구)으로 용도 전환.

#### [PV-H3] 가설 H3 Stop — 전달 경로 교체
- **인쇄물 자동 생성**: QR 열람 대신 구조화 입력의 산출물을 인쇄 복약 카드로 — 프린터 보유 약국부터(PH12·PH15 실태 기준).
- **가족 폰 경유 설계**: 환자 폰 전제를 버리고 보호자 폰을 1차 수신처로(가설 H6 결과와 결합) — 공용폰·무폰 세그먼트 대응.
- **피처폰 채널 검토**: SMS 등 저사양 채널 — 단, 전화번호 수집이 현재의 무수집 원칙([01-dataflow §8.1](../01-dataflow.md), D13)과 충돌하므로 프라이버시 설계를 먼저 다시 세워야 한다. 이 충돌을 해소하지 못하면 후보에서 제외한다.

#### [PV-H4] 가설 H4 Stop — 신뢰 주체 교체
- **발급 주체 격상**: 약국 단독 발급이 아니라 병원·의사 명의의 공식 발급으로(승인 경로 D19·H19 정보가 이미 있음) — 신뢰 원천을 개인 약국에서 기관으로.
- **물리 신뢰물 결합**: 약국 도장·서명이 있는 종이에 QR을 병행 인쇄 — 디지털 단독 신뢰를 요구하지 않는 하이브리드.
- **링크리스 설계**: 열람을 링크가 아니라 그 자리 화면·인쇄물로 완결(TRUST-4 종이 위계가 강할 때).

#### [PV-H5] 가설 H5 Stop — 입력 주체·방식 교체
- **입력 주체 이동**: 처방 시점의 의사·병원 약제부 입력(D16 문항의 "정보가 모이는 시점" 데이터 활용) — 약국은 전달만.
- **입력 최소화**: 자유 구조화 입력을 버리고 사전 인쇄된 패턴 카드·스탬프 세트로(입력 0초, 표현력 축소를 감수).
- **기존 도구 편승**: 약국이 이미 쓰는 POS·청구 소프트웨어에 끼워 넣는 연동 — RISK-5(도구 이탈 이력)가 "새 도구 추가" 자체를 기각할 때의 경로.

#### [PV-H6] 가설 H6 Stop — 공유 축 정리
- **v0 제거**: 공유 버튼·보호자 요소를 제거하고 개인 열람으로 단순화(D12의 공유 URL 처리만 잔존).
- **역전 설계**: 반대로 관여 신호가 "환자 아닌 보호자가 전부"라면 보호자를 1차 사용자로 재정의(수령·열람·질문의 주체) — PM8의 내부 구성(누가 관여하는가)이 근거.

### 3.7 소표본 해석 규칙 (SS1~SS7)

표본이 작으므로(환자 12~15명, 약사 6~8명) 아래 규칙 없이는 §3.3의 임계값이 과신을 만든다. 판정 메모의 모든 수치 서술에 적용한다.

#### [SS1] (필수) 분수 병기와 분모 명시
- 모든 비율은 분수를 병기한다 — "75%(9/12)". 분모는 판정 가능 응답자이며, 건너뛰기·미실시로 분모에서 빠진 인원수를 함께 보고한다. 분모가 8 미만이면 비율 대신 인원수로만 서술한다.

#### [SS2] (필수) 통계 언어 금지
- 임계값은 사전 합의된 채택 규칙이지 가설 검정이 아니다. 판정 메모에 p값·유의성·신뢰구간을 쓰지 않는다. "경향이 보인다", "n명 중 m명에서 관찰됐다"로 쓴다.

#### [SS3] (필수) 강도 가중
- 판정 분자에는 E1·E2만 넣는다(E3 배제 — §2.4). 경계 판정(JR6)에서는 분자의 E1 비중을 본다: E1이 절반 이상이면 계량 방향을 유지하고, E2뿐이면 보수 쪽으로 내린다. CULT-3(체면 보정) 태그가 붙은 참가자의 +방향 자기 보고는 분자에서 제외한다.

#### [SS4] (필수) 하나 빼기 점검
- 임계값 근처의 지표는 가장 극단적인 참가자 1명을 제외하고 재계산한다. 제외 전후로 판정 구간이 바뀌면 그 지표는 경계로 강등한다(JR6). 단일 사례가 판정을 뒤집는 구조를 그대로 두지 않는다.

#### [SS5] (필수) 쿼터 미달 시 판정 불가
- 가설 판정에 필요한 서브그룹이 쿼터([01 문서 §2.2](01-goals-participants-screener-consent.md)) 최소 인원에 미달하면 해당 가설은 자동 Hold(판정 불가)다. 기준 수치는 쿼터표가 유일한 정본이다 — **저문해 4명 미만**이면 가설 H2, **피처폰·공용폰 각 3명 미만**이면 가설 H3의 해당 하위 판정, **1인 운영 약국 2곳 미만**이면 가설 H5의 일반화. 미달 상태에서 Go/Stop을 선언하지 않는다.

#### [SS6] (필수) 삼각검증
- Go·Stop 확정에는 **진술(질문지)·행동(과업)·관찰(O)** 세 원천 중 2개 이상의 방향 일치가 필요하다. 원천이 모순되면 행동 > 관찰 > 진술 순으로 무게를 두되, 모순 자체를 판정 메모에 남긴다 — 모순은 대개 CULT-3 또는 질문 설계 문제의 신호다.

#### [SS7] (필수) 현장 편중 점검
- 한 현장(약국·병원)에서만 나온 신호로 가설을 Go/Stop 하지 않는다 — 최소 2개 현장의 교차를 전제로 한다. 태그 집계에 현장 유형 코드를 유지하고, 특정 현장이 특정 코드의 태그를 절반 이상 만들고 있으면 판정 메모에 "현장 편중"을 표기한다. 순서 효과(조사 후반에만 나타난 신호 — 질문지 수정의 산물일 수 있음)도 변경 로그와 대조해 점검한다.

### 3.8 판정 회의 운영

**중간 가판정 (목표 표본의 약 절반 시점, 60분)**

- 목적은 조기 Stop 신호의 감지와 조사 설계의 교정이지 판정 선언이 아니다. PM 지표를 가집계하고, Stop 구간에 들어간 지표가 있으면 남은 세션에서 반증 기회를 의도적으로 배치한다(예: PM3이 낮으면 인쇄 QR 크기 변형을 투입, PM2가 낮으면 저문해 리크루팅 강화).
- 중간 가판정에서 코드북 대개편(CB2·CB3)을 함께 처리한다 — 후반 세션이 같은 코드 정의로 태깅되도록.

**최종 판정 회의 (현장 종료 후 3영업일 내, 2~3시간)**

- 참석: 진행자 전원, 기록 담당. 통역자는 인용 확인이 필요한 안건에 부분 참석.
- 입력물: 태그 집계표(§2.6, 최종 코드북 버전 명시), 가설별 증거 원장(DB2 누적), NT6 과업 격자 합본, 관찰 탈리 합본, PM1~PM10 산출표, 코드북·질문지 변경 로그, 쿼터 시트 최종본.
- 진행 순서: ① SS5 쿼터 점검(판정 가능 여부) → ② 가설별 GS 판정(각 20분 상한, 경계 지표는 JR6 절차로 확정) → ③ JR 종합 판정(JR2 → JR3 → JR4 → JR7 → JR1 → JR5 — §3.4의 판정 순서와 동일) → ④ Go면 결정 초안 작성, Hold면 HQ 계획, Stop이면 PV 선택 → ⑤ [01-dataflow.md](../01-dataflow.md) 결정 레지스터·미결정 목록에 반영할 항목 정리.
- 이견 처리: 판정이 갈리면 해당 원자료(원문 인용·과업 기록)로 돌아가 1회 재검토한다. 그래도 갈리면 보수 쪽 판정(Go↔Hold 갈림은 Hold, Hold↔Stop 갈림은 Hold)을 채택하고 소수 의견을 판정 메모에 남긴다.
- 산출물: **판정 메모 1부** — 가설별 판정 + 근거(지표값·분수·핵심 인용 ID) + 경계·편중 표기 + Hold/Stop 후속 계획. 판정 메모의 모든 주장 옆에는 참가자 코드·항목 ID가 붙어야 한다. 파일럿 후보 약국 목록(PM9)은 연락 동의서와 함께 노트와 분리 보관한다.
