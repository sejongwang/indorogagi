The screen starts at the pharmacy counter.

Scene 02 · Entry

Scan once. Read in the browser.

The page opens without an app install or account. Before showing instructions, it establishes the pharmacy source, makes English explicit, and avoids putting medicine names in the URL.

  • Patient momentScans the QR with a low-cost Android phone.
  • Interface moveShows pharmacy identity, language choice, and a plain browser page.
  • Error preventedAbandoning the task because of sign-up, installation, or an unfamiliar link.

Scene 04 · Core reading path

A day becomes the information architecture.

Instead of a matrix, instructions are grouped into a fixed four-part rhythm: Morning → Noon → Evening → Night. Empty times stay visible so the sequence never changes between prescriptions.

  • Patient momentScrolls in the same direction that the day progresses.
  • Interface moveRepeats time icon + label, then packet + medicine + amount.
  • Error preventedReading across the wrong row or mistaking “none” for missing data.

Scene 05 · Every instruction

Four visual sentences describe the action.

Each medicine card combines redundant cues. Colour supports recognition, but number and label carry meaning. Dose, food order, duration, and measurement are all explicit.

  • Patient momentChecks one packet immediately before taking it.
  • Interface moveUses icon + number or icon + short label, never icon alone.
  • Error preventedWrong packet, wrong amount, wrong meal timing, or wrong duration.

Scene 06 · Outside the daily rhythm

Exceptions are separated, not squeezed into the timetable.

Weekly, custom, and only-when-needed medicines live in a distinct zone below the daily flow. PRN instructions show each-time amount, daily maximum, and minimum gap together.

  • Patient momentNeeds a medicine only on Sunday, or only when fever occurs.
  • Interface moveMoves exceptions into a clearly titled special section.
  • Error preventedTreating a weekly or PRN medicine as a daily scheduled dose.

Scene 07 · Secondary actions

Details and sharing wait until the core task is complete.

Medicine details expand only when requested. WhatsApp, link copy, and screenshot guidance sit below the instructions, with a privacy reminder that the token link can be opened by anyone who receives it.

  • Patient momentChecks a detail or asks a family member to help later.
  • Interface moveKeeps optional actions collapsed and visually quieter.
  • Error preventedLetting sharing tools or media placeholders compete with the next dose.

Scene 08 · When the guide cannot open

Failure states tell the truth—and nothing more.

Preparing and expired pages provide a safe next step. A revoked link deliberately reveals only that it is unavailable: no pharmacy, reason, or medicine details are exposed.

  • Patient momentOpens a guide before sync, after expiry, or after the pharmacy disables it.
  • Interface moveAuto-retries while preparing, sends expired guides back to the pharmacy, and keeps revoked links information-minimal.
  • Error preventedFollowing old instructions or learning sensitive context from a disabled token.

Scene 09 · End state

The patient leaves with four answers, not a dashboard.

The English experience is successful when the patient can find the next time and packet in seconds, then confirm amount, meal relation, and duration without decoding a table.

  • Patient momentReturns to the same guide at the next dose or shows it to family.
  • Interface movePreserves one reading path across simple and complex prescriptions.
  • Local validationEnglish wording, icons, and operational handoff still require field testing in Indian pharmacies.
